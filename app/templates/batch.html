批次定义怎么写 / 验收口径
  • tables[].old/new 复用单表 schema JSON；consumers 可省略。
  • tasks[].joins[]：{left, left_key, right, right_key}；tasks[].projections[]：{table, column}。任务引用的列以旧 schema 为准（旧口径对账）。
  • 关联键对账：新旧 schema 下两侧键列各自解析到哪一列、什么类型、还能不能关联；旧列名被新列占用 → 关联错列（阻断）。
  • 投影对账：输出列在新 schema 下是否还在、类型是否还可读；被删 → 数据丢失（阻断）。
  • 结论：全部任务完成且无失败、无阻断、无待确认 → 整批通过；否则不可发布；中断的半批结果不能标通过。

验收语义（重放 / 续跑 / 重试）

与结果页一致
  • 断点续跑：任务逐个执行、逐个落盘；中断后「续跑」只执行未完成的任务，已完成/已失败的不重跑。
  • 失败隔离：单个任务定义非法只标记该任务失败，其余任务照常；有失败任务的批次不能通过。
  • 半批不标通过：只要还有未完成任务，结论为空，状态为「已中断」。
  • 失败保留旧版：整批未通过时，同批次最近一次通过的验收仍是生效结论。
  • 输入变化即作废：批次输入指纹变化后，旧通过结论自动作废（页面标注）。
  • 重试不混用：重试 = 同一输入快照新建一次验收（新 id）从头执行，两次结果互不混用；复核记录与下载清单指向同一次验收。
